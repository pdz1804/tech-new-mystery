7 Root Cause Analysis

Root Cause: The Terraform branch chore/disable-ecs-alb-redis-billing successfully set ECS desiredCount=0 and destroyed most ALBs, but did not destroy the NAT Gateways or the final ALB. These infrastructure components continue to charge hourly regardless of whether any workloads use them.

Why do NAT Gateways keep charging?

AWS NAT Gateways are billed on two dimensions: (1) hourly presence at $0.045/hr, and (2) data processing at $0.045/GB. Setting ECS tasks to 0 eliminates data processing fees but does NOT stop the hourly charge. The only way to stop NAT Gateway hourly charges is to delete the NAT Gateway resource itself (via AWS console, CLI, or Terraform terraform destroy on the resource). Simply stopping workloads is insufficient.

Why does the ALB keep charging?

Similarly, ALBs bill an hourly rate ($0.008/hr) plus LCU charges based on traffic. The LCU charges are near-zero since there's no traffic, but the hourly fixed cost accumulates. The final remaining ALB must be deleted (not just have its targets set to 0) to eliminate these charges.

Why NAT Gateways are required for DeepResearch (unlike tech-news-mystery)
The DeepResearch ECS service uses private subnets with assignPublicIp=DISABLED. Tasks in private subnets have no direct internet path — they must route outbound traffic through a NAT Gateway to reach AWS APIs (Bedrock, ECR, Secrets Manager, etc.). Without a NAT Gateway, ECS tasks in those private subnets cannot start (they can't pull the container image from ECR or reach Secrets Manager).
